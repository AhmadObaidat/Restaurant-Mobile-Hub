# Restaurant Loyalty Platform

A white-label restaurant app platform for independent food businesses in Jordan, with Arabic-first customer experiences and a path to separately branded restaurant applications.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)

## Where things live

- `artifacts/mobile` — customer-facing Expo app preview; its restaurant configuration, Arabic/English copy, local state, and screens live here.
- `artifacts/api-server` — shared Express API service.
- `lib/api-spec` — OpenAPI source of truth for shared API contracts.
- `lib/db` — Drizzle database package and schema.
- `artifacts/mockup-sandbox` — canvas-backed component preview environment.

## Architecture decisions

- The customer app is one reusable Expo codebase with four fictional restaurant configurations; branding and menu content are configuration-driven.
- The current mobile deliverable stores preview carts, points, rewards, preferences, and orders locally per restaurant. It is not connected to the shared API.
- Checkout and reward redemption are explicitly demos. No payment, restaurant fulfillment, or points verification occurs.
- Planned app identifiers are preview metadata; restaurant-specific signed builds and store submissions are not generated by this artifact.

## Product

The platform is intended to give independent restaurants branded customer apps for menu browsing, ordering, loyalty, and promotions, managed through shared services. The current deliverable is the mobile customer preview, not the full SaaS administration and restaurant-management platform.

## Gotchas

- Do not treat locally stored sample points, order totals, redemption codes, or delivery areas as authoritative business records.
- Do not claim live authentication, payment processing, restaurant order delivery, store approval, or production readiness from the mobile preview.
